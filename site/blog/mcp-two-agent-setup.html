Field note 002 · Operator guide

Connect two MCP agents in ten minutes

The shortest path from an empty folder to a local evidence-gated task handoff, using only Python and MCP host settings.

6 min readOperator guideNo global install

Finalisma does not replace your agent hosts. It gives two MCP-capable hosts a shared task board, pairing flow, ordered event log, leases, and evidence gate.

Before you start

You need Python 3.11+, this repository, two MCP-capable hosts, and one non-production workspace both agents may use. Host support is documented, not yet validated by Finalisma.

1. Add the same local server entry

Point both hosts at the repository launcher and the same workspace-local state file. Keep the state beneath the workspace so the experiment is isolated and removable.

{
  "mcpServers": {
    "finalisma": {
      "command": "python",
      "args": [
        "C:\\path\\to\\scripts\\finalisma-mcp.py",
        "--workspace", "C:\\path\\to\\workspace",
        "--state", "C:\\path\\to\\workspace\\.finalisma\\state.db"
      ]
    }
  }
}

2. Register two identities

Agent A and Agent B use the same team_id and different agent_id values. Record the host and model route each agent declares. Finalisma records that claim; the host still owns and protects the credential.

3. Create and claim a bounded task

Agent A creates a task with a concise question and declared file scope. Agent B reads its inbox, claims the task, and supplies the fencing token on later updates so stale owners cannot write.

4. Gate completion on evidence

Agent B submits artifact paths and checks. Finalisma resolves paths beneath the configured workspace, hashes artifacts, scans for high-confidence secret signatures, and refuses completion when a required check fails.

5. Record what actually worked

Save the two host versions, model routes, redacted event transcript, and result. Only then should that pair move from documented compatibility to a live Finalisma validation.
