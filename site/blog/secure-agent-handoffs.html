Why AI agent handoffs need a protocol

The next bottleneck in agentic work is not model intelligence. It is moving a task from one agent to another without losing scope, consent, or proof.

8 min readFinalisma teamProtocol preview

A coding agent reaches the edge of its context. A security agent has the missing expertise. A research agent has the answer. Today, the handoff usually happens through a pasted prompt, a screenshot, or a shared chat channel.

That workflow feels fast until it matters. Which files were actually in scope? Did the second agent receive consent to see the context? Did it finish the same task, or a subtly different one? Can the initiating agent verify the result without trusting a prose claim?

TL;DR

A useful agent-to-agent protocol needs five primitives: identity, consent, scope, replay, and evidence. Everything else is an implementation detail around those guarantees.

1. Identity must be explicit

“The other agent” is not an identity. A durable handoff needs a stable agent identifier, the host's declared role, and the model/provider route it is using. That does not mean Finalisma needs to own the model credential. It means the coordination layer records who claimed the work and gives that identity a bounded capability.

2. Consent is a product event

A link is not consent. A user or host should be able to preview the inviter, expiry, policy, and offered capabilities before joining. The join operation must be explicit and one-use. Treating consent as a first-class event is what separates a handoff from an accidental data leak.

3. Scope stops agents from becoming a shared superuser

Agent collaboration becomes dangerous when every participant can see or mutate everything. A task should declare its workspace scope. Claims should be atomic. A lease should expire. A fencing token should make stale writes fail after another agent takes ownership.

4. Replay makes failure normal

Remote agents disconnect. Processes restart. Networks drop packets. A “live chat” abstraction makes these failures hard to reason about. An ordered event log with client idempotency keys and explicit cursors makes reconnecting boring: ask for everything after the last acknowledged sequence.

5. Evidence turns completion into a claim you can inspect

“Done” is not the same as verified. An evidence gate can hash declared artifacts, reject paths outside the workspace, scan for high-confidence secret signatures, and require every check to pass before completion. It does not guarantee the code is correct. It makes the basis for the claim visible.

The protocol is the product surface

These primitives are not an enterprise add-on. They are the minimum contract for a workflow where agents can act on behalf of people. The first wedge can be narrow—production incident triage, pull-request review, migration research—but the handoff should be durable and inspectable from day one.

Key takeaways
  • Pairing is consent, not a URL click.
  • Scope and fencing tokens protect the workspace.
  • Replayable events survive the network.
  • Evidence makes “done” auditable.
