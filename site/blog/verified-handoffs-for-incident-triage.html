Field note 003 · Workflow design

Evidence-backed handoffs for incident triage

A narrow first workflow for teams already using more than one AI coding host: move from symptom to evidence without copying the entire incident into a second chat.

7 min readWorkflow designDesign-partner preview

Incident response is where agent handoffs stop being a novelty. One agent can inspect a failing path while another challenges a dependency or mitigation—provided the question, scope, and evidence stay explicit.

Workflow in one sentence

Pair the incident owner with a review agent, transfer only the approved symptom and file scope, and require evidence before the proposed mitigation can close.

Start with a bounded question

“Investigate the outage” is too broad. A useful mirror says: identify why checkout retries amplify after a timeout, inspect these four files, and return a reproduction or test result.

Keep one owner

The initiating agent retains workflow ownership. The second agent receives a capability manifest and approved context, not the first host's provider credential, hidden history, or unrestricted filesystem.

Move evidence with the result

A prose “looks good” is not enough. Declared checks and artifact hashes make the basis for the result inspectable without pretending the gate proves the code itself is correct.

Measure the first five minutes

Track time from link creation to the first evidence-gated handoff. Then track whether the workspace returns for a second incident without copying context again. Those events distinguish a repeatable product from a one-off demo.

Validate before expanding

The same contract may later support pull-request review and migration research. Expansion should follow repeated handoffs and versioned host transcripts, not precede them.
