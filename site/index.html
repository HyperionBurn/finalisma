Finalisma Field Notes01 — The unposted account

Finalisma is a coordinator for verified agent handoffs, a fittingly dry name for a genuinely unglamorous problem. Two AI agents keep one account of a single piece of work. One agent asserts — usually a coding agent that has run out of context, opening a scoped task and declaring exactly which files sit inside it. The other proves — it previews the policy it is being asked to work under, consents to that policy on the record, and claims the task under a lease carrying a fencing token, so a slow or stale claim cannot quietly overwrite a newer one.

Today, most teams skip all of that machinery and move the work by hand: a prompt, a file list, half a page of reasoning pasted into a second chat window, and a result copied back the same way it arrived.

On the unposted handoff

The honest boundary

This preview is not hosted, multi-tenant software. What runs today is a durable single-node coordinator built on the Python standard library and SQLite — enough for a design-partner pilot on a trusted network, not for public multi-tenant scale. Serving many tenants honestly still needs OAuth or OIDC, shared storage, distributed rate limits, and the operational controls hosted products are usually expected to have already.

The first account this is built for is an incident under triage. An on-call agent has findings and no authority to ship the fix; the agent that could review and merge it has no reliable channel for receiving those findings. MCP is the tool protocol your hosts already speak; Finalisma adds the scoped handoff and the evidence gate on top of it, as an MCP server rather than a third agent competing for the job.

Finalisma never chooses a model and never executes a command it finds inside a message payload. What actually crosses the wire is narrower and more boring than a whole session: a scoped task, a recorded consent, a lease, and the evidence that the work underneath it was actually done. None of it requires either agent to take the other's word for anything — only a coordinator neither one controls, keeping a record both of them can be held to.

Fig. 1

Seven checkpoints between a finding and a fix

The sequence below mirrors the documented protocol exactly. Every checkpoint is enforced by the coordinator, not left to either agent behaving well — including the last one, where a stale claim arrives after ownership has already moved and is refused at the gate.

  1. 01
    Pairing link issued

    One agent issues a one-time, single-use link before the second identity ever joins.

  2. 02
    Policy previewed

    The receiving agent reads the offered policy before it agrees to anything.

  3. 03
    Consent recorded

    That agreement is written down on the record, not assumed from silence.

  4. 04
    Scope declared

    The task states exactly which files it is allowed to reference, up front.

  5. 05
    Task claimed

    An atomic claim under a lease, carrying fencing token 0184, so a stale claim fails loudly instead of landing quietly.

  6. 06
    Evidence gated

    Artifacts are hashed, paths are checked against scope, secrets are scanned, and completion blocks until every submitted check passes.

  7. 07
    Handoff returned

    The result returns over stdio or Streamable HTTP — ordered, idempotent, and replayable if the connection drops.

Illustrative sequence, drawn from the documented protocol — not telemetry from a live session. Read the protocol.

Finalisma Field Notes03 — Queries on file

Frequently asked

Does Finalisma run the models?

No. It coordinates task and session state only. Your agent host keeps its own model credentials, provider execution, filesystem permissions and approval interface, and the model route recorded against a task is a label rather than a substitution.

Which hosts can connect?

Any host that speaks MCP, either directly over stdio or through the authenticated Streamable HTTP endpoint. A product without MCP needs a native connector, and the protocol document is the adapter contract for writing one. Nothing is installed into another product silently.

Is this hosted SaaS?

Not yet, and the page says so deliberately. What ships today is a durable single-node coordinator on SQLite, which is enough for design partners and trusted-network trials. Hosted multi-tenant traffic still needs shared storage, OAuth or OIDC, distributed limits and operational controls.

What happens when an agent disconnects?

Session events are totally ordered, idempotent, and replayable from the last acknowledged cursor, so reconnecting is an ordinary operation rather than a recovery. Task leases and fencing tokens make stale work fail instead of landing quietly — the failure Fig. 1 draws.

Where do credentials live?

Nowhere in Finalisma. A pairing link carries a one-time token in the URL fragment, session credentials are bound to the member that consented, and the HTTP transport reads a bearer token from your secret manager — never from the repository, the payloads or the logs.

Can a task make it run a command?

No. Finalisma refuses to execute shell commands found in message payloads and never writes into a host's settings. It routes and verifies work; execution stays with the host that owns the permissions.
