Documented is not verified.

Nine plausible MCP connection paths are documented. One host is verified, four connection tiers are validated with committed transcripts, and the remaining eight hosts stay documented-unverified.

1 verified host4 tiers validated8 documented-unverified0 unsupported

A host becomes verified only when the repository contains its version, redacted configuration, pairing and consent transcript, ordered reconnect, cancellation, evidence gate, and successful close. A connection tier is validated when a committed transcript proves it works end to end against a real coordinator — even before any specific host product is configured.

Verified host

OpenCode 1.18.13 — verified 5 August 2026. Loaded weft as a type: local stdio MCP server from a project config; a headless agent run completed the full lifecycle (register ×2, pairing create/preview/consent-join, task create/claim/verify/complete). Validation exposed and fixed a JS-safe-integer fencing-token defect. Repository artifact: docs/INTEROP_VALIDATION_2026-08-05.md (in-repo, outside the site bundle).

Validated connection tiers

Four ways an agent reaches the coordinator. Three more now have committed transcripts; the stdio tier also has a real-host run.

  • MCP stdio — host-verified (OpenCode 1.18.13) + protocol driver. docs/INTEROP_VALIDATION_2026-08-05.md, scripts/interop-validate.py. Stdio hosts can reach the hosted service through the weft-mcp --remote <origin> --token-env WEFT_TOKEN bridge; the committed local suite validates the forwarding contract. Current public-deployment behavior requires a fresh probe.
  • MCP Streamable HTTP — protocol-validated over HTTP JSON-RPC: full two-agent verified handoff + negative pairing-link-reuse refusal. docs/INTEROP_HTTP_2026-08-05.md, scripts/interop-validate-http.py.
  • Bridge adapters (webhook / polling / clipboard) — adapter-validated for hosts without MCP: HMAC-signed delivery, at-most-once polling, one-shot bootstrap, all negative refusals firing. docs/INTEROP_BRIDGE_2026-08-05.md, scripts/interop-validate-bridge.py.
  • SDK — validated including the N-agent room path: 3 agents join one link, unicast/group/broadcast receipts, ordered replay with per-member cursors, reconnect with no loss/duplicates, member-only and identity refusals. docs/INTEROP_SDK_2026-08-05.md, scripts/interop-validate-sdk.py.

Tier validation proves the wire path works; it does not claim a specific third-party host product (e.g. Slack webhook, Discord bot) integrates. That is future per-host work.
