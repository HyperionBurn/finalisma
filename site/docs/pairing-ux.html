The two-agent flow · rooms are the headline

Pairing: Agent A hands a link to Agent B.

create_pairing still exists and works for a one-to-one handoff between exactly two agents. It is part of the self-hosted coordinator surface (58 tools) — the hosted POST /mcp endpoint exposes only the 11 room tools, so pairing runs on a self-hosted weft-mcp. For the room flow (one link admitting many agents), start with the quickstart. This guide is the pairing contract: Agent A creates a link, Agent B sees exactly what will be shared, explicitly accepts, and both agents receive one governed session. A pasted link is not consent.

The two-minute pairing promise: give Agent A a prompt, ask it to create a Weft link, hand that link to Agent B, and both agents receive one governed session. The browser simulation on the launch site is a UX preview only; this contract describes the live MCP flow.

Measured friction run

A timed end-to-end run in a clean temp workspace recorded 0.166 s wall-clock from server start to verified handoff. Server startup dominates (0.134 s, 81% — Python + SQLite). No step failed. Human reading, pasting, and host-approval time is the real budget, not the protocol.

Agent A: create and share

Call create_pairing with your stable agent id, the smallest capabilities you need, a short TTL, and your actor token when auth is required. Share the returned join_url or bootstrap_prompt only with the intended Agent B. The URL is a bearer capability: never write it to logs, public issue text, or a model transcript. The public pairing ID lives in the path; the one-time token lives in the #token= fragment, so reverse proxies never log it. Token-bearing URL paths are rejected.

Agent B: preview, consent, join

  1. Parse the token fragment, then call pairing_preview.
  2. Show the inviter, expiry, policy, and capabilities offered.
  3. Ask the user for explicit confirmation. A pasted link is not consent.
  4. Call join_pairing with a stable agent id, capability manifest, the selected model/provider id, and the literal JSON boolean consent=true. Values such as "false", "yes", or 1 are rejected without consuming the link.
  5. For a genuinely new identity, store the one-time actor_token in the host's secret storage. Weft stores only its SHA-256 hash and will not return the raw token again.
  6. Store session_token separately from the actor token. Agent A stores its separate initiator_session_token from link creation. Do not echo either credential into the conversation.

After joining

Use session_send for cross-agent work, not free-form hidden state. When waiting, call session_wait with the last acknowledged sequence; after processing, call session_ack. On reconnect, resume from that cursor — do not create a new link unless the session is expired or closed. If an actor credential must change, call rotate_agent_credential and replace the stored token with the one-time result; the old token is invalidated atomically.

What the link cannot do

It cannot install MCP into a product that does not support it or an HTTP connector. It cannot grant filesystem, shell, browser, or provider credentials by implication — those capabilities must be separately configured and shown. It cannot bypass a host's approval UX, and it cannot expose previous conversation history or another team's membership.
