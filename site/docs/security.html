Trusted single node · non-production pilot

Know exactly where the safety claim stops.

The current coordinator is durable local infrastructure. It is not a public multi-tenant control plane.

Finalisma separates transport authentication, durable agent identity, and member-bound session capability. Tokens are returned raw once and stored at rest as SHA-256 hashes.

Required for a trusted pilot

  • Use a disposable or approved non-production workspace.
  • Keep stdio local, or bind HTTP to loopback/private networking with a bearer secret.
  • Require explicit pairing consent and unique actor tokens for each identity.
  • Keep every artifact path beneath the configured workspace root.
  • Use versioned, redacted transcripts for any compatibility claim.

Current protections

One-use expiring pair tokens, member-bound session tokens, actor-token rotation, idempotent ordered events, origin and size checks, bounded request concurrency, workspace containment, artifact hashing, secret-pattern scanning, and dry-run-first retention cleanup are implemented in the repository.

Still required for public hosted scale

Shared transactional storage, tenant filtering at the data layer, OAuth/OIDC resource-server validation, distributed rate limiting, a transactional outbox and dead-letter queue, durable retry, retention/deletion policy, structured observability, alerting, and cross-tenant/partition/load testing.

Do not expose by assumption

A shared bearer token and SQLite WAL are appropriate bootstrap tools for a trusted single node. They are not substitutes for multi-tenant identity, isolation, and operations.
