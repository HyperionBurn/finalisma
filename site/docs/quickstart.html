10–20 minutes · trusted local workspace

Run one bounded handoff.

This proves the repository's coordination flow. It does not by itself validate either host integration.

Python 3.11+No package installWorkspace-local SQLite

Use a disposable, non-production workspace. Both MCP clients must point at the same Finalisma launcher, workspace root, and state file.

Safety boundary

Do not use production credentials or production incident data. Finalisma coordinates declared work; it does not need either model provider key.

1. Prove the coordinator before connecting hosts

python -B .\scripts\finalisma-smoke.py

A successful run exercises registration, task routing, claims, updates, evidence, and completion without touching host settings.

2. Add the same MCP server entry to both hosts

{
  "mcpServers": {
    "finalisma": {
      "command": "python",
      "args": [
        "C:\\path\\to\\Multiplayer-AI\\scripts\\finalisma-mcp.py",
        "--workspace", "C:\\path\\to\\incident-mirror",
        "--state", "C:\\path\\to\\incident-mirror\\.finalisma\\state.db"
      ]
    }
  }
}

The exact UI and configuration filename vary by host. Review the command before approving it. A non-MCP host requires an adapter.

3. Register Agent A and Agent B

Use the same team_id, unique agent_id values, and the exact model routes each host declares. Persist each one-time actor_token in that host's secret storage; never paste it into a task.

4. Run the account

  1. Agent A calls finalisma_create_task with a bounded question and file scope.
  2. Agent B reads its inbox, claims the task, and keeps the fencing token.
  3. Agent B posts progress or a question with its own actor token.
  4. Agent B submits artifact and check evidence through finalisma_verify_task.
  5. Only an evidence-gated task can call finalisma_complete_task.

5. Capture a validation transcript

Record host and extension versions, redacted configuration, tool discovery, consent, reconnect, cancellation, evidence, and completion. Until that artifact exists, describe the host path as documented—not verified.

Cleanup

Stop both clients, then remove only the .finalisma directory inside the disposable workspace.

Do not infer

A listed MCP transport proves a configuration path exists. It does not prove the host follows Finalisma's complete workflow.
