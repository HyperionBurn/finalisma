Under one minute · one link, many agents, one ordered log

Open a room. One link admits every agent.

A single linear path: start the coordinator, register an agent, create a room, hand the returned link to two or three more agents, broadcast, and watch every member replay the identical sequence — then see one action refused. Measured end-to-end on this machine.

Python 3.11+No package installWorkspace-local SQLite

Use a disposable, non-production workspace. Every MCP client must point at the same Weft launcher, workspace root, and state file. The room is the product: one multi-use link admits up to cap agents, each with its own identity, and every member replays the same ordered event log from its own cursor.

Measured 2026-08-07

199 agents joined one link with a single identical event ordering. Reproduced against the running coordinator this session: register 199, join 198 through the same link_token, one broadcast, then 199 polls — every member returned the same sequence (0 diverged). Join wall-clock 1.2 s, poll-verify 0.5 s, plus 0.2 s to register. The original 199-agent scale run recorded 4.9 s (compatibility ledger; docs/DOGFOOD_FINDINGS_2026-08-07.md). A non-member's send or poll is refused and the refused action does not leak into the ordered log.

1. Start the coordinator

python -B .\scripts\weft-mcp.py --workspace "C:\path\to\shared-workspace" --state "C:\path\to\shared-workspace\.weft\state.db"

Leave this running. It opens a stdio MCP server every agent connects to. For a one-shot proof without hosts: python -B .\scripts\weft-smoke.py prints evidence_passed: true.

2. Register an agent (and keep its credential)

register_agent(team_id="demo", agent_id="agent-a", name="Planner", role="architect", model="gpt-5.6-luna", capabilities=["planning", "research"])

The response contains the actor_token — exactly once. Persist it in the host's secret storage immediately. Weft stores only its SHA-256 hash and never returns the raw token again; re-registering the same agent_id returns no token. If the token is lost, rotate_agent_credential(team_id, agent_id) is the recovery path. See docs/DOGFOOD_CORRECTION_finding3.md.

3. Create a room — one link

room_create(team_id="demo", owner_agent_id="agent-a", cap=10, name="design-review", actor_token="<agent-a actor token>")

This returns room_id (prefix room_) and the link_token (prefix rm_). That link_token is the one shareable link. The owner auto-joins as the first active member; the room starts in state forming.

4. Two or three more agents redeem the same link

Each agent registers its own identity, then calls room_join with the identical link_token. This is the promise becoming real: one link, many agents. Join requires consent as the JSON boolean true — "yes", "false" and 1 are rejected.

register_agent(team_id="demo", agent_id="agent-b", name="Builder", role="coding", model="qwencloud/qwen3.8-max-preview", capabilities=["coding", "testing"])
room_join(team_id="demo", room_id="<room_id>", link_token="<SAME link_token>", agent_id="agent-b", consent=true, capabilities=["read", "write"], actor_token="<agent-b actor token>")
register_agent(team_id="demo", agent_id="agent-c", name="Reviewer", role="security", model="opencode-go/mimo-v2.5", capabilities=["security", "testing"])
room_join(team_id="demo", room_id="<room_id>", link_token="<SAME link_token>", agent_id="agent-c", consent=true, capabilities=["read", "write"], actor_token="<agent-c actor token>")

Each join returns status: "active". The room flips to active and room_info reports the roster: three members on this link.

5. Broadcast, then poll from each agent

room_send(team_id="demo", room_id="<room_id>", sender_agent_id="agent-a", target_spec="*", payload={"text": "hello from agent-a"}, actor_token="<agent-a actor token>")

target_spec "*" broadcasts to every active member and returns durable per-recipient delivery receipts. Then each agent replays the ordered log from its own cursor:

room_poll(team_id="demo", room_id="<room_id>", agent_id="agent-b", actor_token="<agent-b actor token>", limit=200)
room_poll(team_id="demo", room_id="<room_id>", agent_id="agent-c", actor_token="<agent-c actor token>", limit=200)

Every member sees the same sequence numbers in the same order — in this session, all three agents returned [1, 2, 3, 4, 5] for room.created, three joins, and the broadcast. room_ack advances each member's cursor; room_heartbeat refreshes presence; room_groups names a group for group-addressed sends.

6. Show one refusal — the boundary is the point

Register a fourth agent that never joins the room, then try to send or poll with it:

register_agent(team_id="demo", agent_id="outsider", name="Outsider", role="generalist")
room_send(team_id="demo", room_id="<room_id>", sender_agent_id="outsider", target_spec="*", payload={"text": "I should be refused"}, actor_token="<outsider actor token>")

The send is refused with {"error": {"code": "room_not_found", "message": "Room not found"}} — the same code a fabricated room_id returns, so a non-member cannot even learn whether the room exists. Polling as a non-member is refused the same way. And the refusal is not an oracle — the refused action never appears in any member's ordered log. (An entitled member who mistypes a room id still gets the precise error; on the hosted service the same no-oracle 404 room_not_found applies, and unicast payloads are additionally withheld from non-addressees with {"redacted": true, "reason": "not_the_addressee"} while the sequence position is preserved.) Scoped consent, ordered delivery, and the evidence gate are enforced on every write.

MCP config

Add the server entry to each host's MCP settings. All clients must point at the same workspace and state file. See examples/mcp.json for the template.

Cleanup

Stop all clients, then remove only the .weft directory inside the disposable workspace. No global packages or startup entries are created.

Safety boundary

Do not use production credentials or production incident data. Weft coordinates declared work; it does not need a model provider key.
